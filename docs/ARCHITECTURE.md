# بنية التطبيق

## نظرة عامة

يتبع المشروع بنية Laravel التقليدية مع فصل مسارات الويب وAPI، والمتـحكمات، وطلبات التحقق، ونماذج Eloquent، والسياسات، والإشعارات، وواجهات Blade. يجمع التطبيق بين حارس المستخدم الافتراضي وحارس مستقل للشركات، بينما تحمي Sanctum عدداً من نقاط API.

```text
Client (Browser / Mobile)
        |
        v
routes/web.php  ─────┐
routes/api.php  ─────┼──> Middleware / Guard ──> Controller ──> Model / Policy
                     |                                      |            |
                     |                                      v            v
                     |                                Blade / JSON   Database
                     v
              Notifications / Mail / Storage
```

## تقسيم المجلدات

| المسار | المسؤولية |
|---|---|
| `app/Http/Controllers` | تنسيق طلبات HTTP وتنفيذ حالات الاستخدام. |
| `app/Http/Middleware` | التحقق من الدخول والدور واعتماد الشركة والسائق. |
| `app/Http/Requests` | قواعد التحقق المعاد استخدامها للطلبات. |
| `app/Models` | نماذج Eloquent وعلاقات النطاق التشغيلي. |
| `app/Policies` | قواعد التفويض على الموارد. |
| `app/Notifications` و`app/Mail` | الرسائل والإشعارات داخل النظام والبريد. |
| `database/migrations` | تطور مخطط قاعدة البيانات. |
| `resources/views` | واجهات Blade ومكونات العرض. |
| `routes/web.php` | الواجهات المتصفحـية والجلسات. |
| `routes/api.php` | نقاط JSON للعميل الخارجي أو الهاتف. |
| `config` | إعدادات التطبيق والحراس والخدمات والتخزين والبريد. |

## الأدوار والحراس

| الهوية | الحارس أو الوسيط | الاستخدام |
|---|---|---|
| المستخدم/المسافر | `web` و`auth` أو `auth:sanctum` | الملف الشخصي، الحجوزات، الدفع، التقييمات. |
| الشركة | `company` و`auth:company` أو `ApprovedCompany` | الرحلات والحافلات والسائقون وإدارة الحجوزات. |
| المشرف | `auth` و`AdminMiddleware` | لوحة الإدارة وتغيير حالات الشركات والمستخدمين. |
| السائق | `EnsureDriverApproved` عند تفعيله في المسار | عمليات السائق والحالة والوثائق. |

يعرّف `config/auth.php` مزود `users` ومزود `companies` مستقلاً. عند إضافة مسار جديد، اختر الحارس الصحيح أولاً، ثم تحقق من ملكية المورد داخل المتحكم أو السياسة؛ لا يكفي إخفاء خيار الواجهة لمنع الوصول.

## النطاقات التشغيلية

### الرحلات والحجوزات

تملك الشركة مركبات وسائقين ورحلات. ترتبط الرحلة بمركبة وسائق وشركة، ثم تنشئ المقاعد الخاصة بها. ترتبط الحجوزات بالمستخدم والرحلة والمقعد. يجب أن تبقى عملية إنشاء رحلة ومقاعدها ذرية داخل معاملة قاعدة بيانات، وأن تُراجع حالة المقعد عند الحجز أو الإلغاء.

### الشركات والسائقون

حساب الشركة منفصل عن حساب المستخدم. تعتمد حالة الشركة والسائق قبل إتاحة العمليات الحساسة. تخزن الوثائق والشعارات عبر العلاقة متعددة الأشكال `Document` حيثما يلزم.

### الإدارة والإشعارات

تتعامل لوحة الإدارة مع اعتماد الشركات وحظر المستخدمين. تستخدم نماذج الإشعارات لتنبيه الكيانات ذات الصلة بتغييرات الحالة والحجوزات والإعلانات. يجب أن تُنفذ مهام الإشعارات أو البريد المكلفة عبر الطابور في بيئة الإنتاج.

## قرارات التصميم المطلوبة عند التوسع

| المجال | المعيار المقترح |
|---|---|
| التحقق | استخدم `FormRequest` للعمليات المعقدة أو المعاد استخدامها. |
| التفويض | أضف Policy أو تحقق ملكية صريحاً لكل تعديل أو حذف لمورد مملوك. |
| API | حافظ على استجابات JSON متسقة ورموز HTTP صحيحة، ثم أصدر نسخة API جديدة عند وجود تغييرات كاسرة. |
| قاعدة البيانات | أضف هجرة جديدة للتغييرات المنشورة؛ لا تعدّل هجرة طُبقت في بيئات قائمة. |
| الأداء | استخدم eager loading للعلاقات المعروضة، والطوابير للإشعارات والبريد. |
| المراقبة | اضبط قناة سجل إنتاجية، وتنبيهات للأخطاء، ومراقبة للطوابير. |

## نقاط انتباه

المشروع يحوي واجهات Web وAPI في وقت واحد، لذلك ينبغي تجنب إعادة استخدام استجابة إعادة التوجيه في مسار API أو إرجاع JSON غير متوقع في مسار Blade. استخدم `expectsJson()` عند الحاجة إلى مسار مشترك، أو افصل حالات الاستخدام عندما تختلف العقود فعلياً.
