# نظام حجز رحلات الحافلات

## نظرة عامة

هذه النسخة تمثل طبقات التطبيق الأساسية لنظام حجز رحلات الحافلات المبني على Laravel. تدعم الشفرة المعروضة أدوار **المسافر** و**الشركة** و**المشرف**، وتغطي البحث عن الرحلات والحجوزات وإدارة الحافلات والسائقين والمدفوعات والتقييمات والإشعارات. أُجريت على هذه النسخة مراجعة تنظيمية محافظة؛ لذلك لا يُحذف أي مورد ما لم يكن خالياً من الارتباطات النصية الداخلية والمسارات المعروفة.

> يحتوي المصدر المستلم على مجلدات التطبيق والمسارات والموارد والإعدادات وقاعدة البيانات فقط، ولا يحتوي على `composer.json` أو `artisan` أو `bootstrap/` أو اختبارات تشغيلية. لذلك يجب تشغيل فحوصات التكامل داخل المستودع الكامل قبل النشر.

## خريطة الوحدات

| الوحدة | نقطة الدخول الرئيسية | المسؤولية |
|---|---|---|
| واجهة المسافر | `FrontController` و`ProfileController` | الصفحة الرئيسية والبحث والملف الشخصي والحجوزات. |
| إدارة الشركة | `CompanyController` و`VehicleController` و`DriverController` | الرحلات والحافلات والسائقون وملف الشركة والإشعارات. |
| لوحة المشرف | `AdminController` ضمن بادئة `/admin` | إحصاءات الإدارة وإدارة المستخدمين والشركات. |
| الحجوزات والدفع | `BookingController` و`PaymentController` | اختيار المقاعد والحجز وإلغاء الحجز والدفع. |
| واجهة البرمجة | `routes/api.php` | عمليات الهاتف أو العملاء الخارجيين المحمية بحسب تعريفات المسارات. |

## المسارات والحدود الأمنية

تفصل المسارات بين الأدوار عبر مجموعات مستقلة. المسافر يستخدم الحارس الافتراضي ضمن `auth`، ولوحة المشرف محمية بـ `auth` و`AdminMiddleware`، أما الشركة فتعمل ضمن `auth:company`. يجب أن يضاف أي مسار جديد إلى المجموعة المناسبة بدلاً من تركه عاماً، وأن تُسمّى المسارات التي تستدعيها واجهات Blade باسم واضح ومتسق.

| المنطقة | المسار الأساسي | الحماية المتوقعة |
|---|---|---|
| المسافر | `/dashboard` و`/trip/*` | `auth` |
| المشرف | `/admin/*` | `auth` و`AdminMiddleware` |
| الشركة | `/company/*` | `auth:company` |
| الواجهة العامة | `/home` و`/search-trips` | عامة |
| API | `routes/api.php` | وفق الوسيط المعلن لكل نقطة نهاية |

تستخدم لوحة الإدارة واجهة `admin-profile` الديناميكية المرتبطة ببيانات المشرف والشركات والمستخدمين، وتبقى نقطة الدخول المعتمدة لها هي `/admin/dashboard`. أزيلت المسارات الإدارية المكررة وغير المحمية.

## بنية المجلدات

```text
app/
  Http/Controllers/   منطق HTTP بحسب نطاق العمل
  Http/Middleware/    تفويض الوصول والتحقق من الدور
  Http/Requests/      قواعد التحقق من الطلبات
  Models/             نماذج Eloquent وعلاقاتها
  Notifications/      إشعارات النظام
  Policies/           قواعد التفويض على الموارد
config/               إعدادات خدمات التطبيق
 database/
  migrations/         سجل تطور المخطط؛ لا يُحذف من نسخة منشورة
  seeders/            البيانات الأولية
resources/views/      واجهات Blade ومكوّناتها
routes/               واجهات الويب وAPI والمصادقة
```

## معايير التطوير المعتمدة

يجب أن تتبع الإضافات الجديدة المعايير التالية للحفاظ على مشروع قابل للصيانة:

1. توضع قواعد التحقق في `FormRequest` عند إعادة استخدامها أو عندما يكون الطلب غير بسيط، ويستعمل `validated()` بدلاً من تمرير كامل المدخلات إلى النموذج.
2. لا تُنشأ واجهة Blade قبل ربطها بمسار أو استدعاء مكوّن واضح. ويجب حذف النماذج الأولية والنسخ المكررة قبل الدمج.
3. لا يُنشأ متحكم فارغ أو أسلوب عام بلا مسار أو مستدعٍ داخلي موثق. إذا كان الأسلوب مقصوداً لخدمة مستقبلية فيسجل في مهمة أو وثيقة واجهة برمجة قبل دمجه.
4. تبقى جميع التعديلات التاريخية على قاعدة البيانات في `database/migrations`؛ تعديل الهجرة المنشورة أو حذفها قد يضر البيئات القائمة.
5. تستخدم أسماء موحّدة بالإنجليزية وفق PSR-12 للفئات والملفات والأساليب الجديدة، مع توثيق الحالات غير البديهية عبر PHPDoc موجز ودقيق.
6. يجب التحقق من الصلاحية والملكية قبل تعديل حجز أو رحلة أو سجل شركة، وخصوصاً في المسارات الإدارية ومسارات API.

## فحوصات ما قبل الدمج

بعد استعادة ملفات Laravel القياسية (`composer.json` و`artisan` و`bootstrap/`)، ينفذ المطور الخطوات التالية من جذر التطبيق الكامل:

```bash
composer install
php artisan optimize:clear
php artisan route:list
php artisan view:cache
php artisan test
```

ثم يُشغّل محلل الشفرة المتفق عليه في المستودع، مثل Laravel Pint وPHPStan أو Larastan، وتراجع نتائج المسارات والواجهات قبل إصدار نسخة إنتاجية.

## سجل التنظيف

تتوافر التفاصيل الدقيقة للملفات والأساليب المحذوفة والتعديلات المحافظة في [CLEANUP_MANIFEST.md](CLEANUP_MANIFEST.md). يظل هذا السجل جزءاً من مراجعة الكود ليسهّل التحقق وإعادة أي تغيير إذا ظهرت تبعية خارج الملفات المستلمة.

## قيود المراجعة

لا يمكن الجزم بسلامة التشغيل الكامل أو بتنظيف تبعيات Composer أو تنفيذ الاختبارات دون ملفات إطار Laravel الكاملة وملف البيئة وقاعدة البيانات المهيأة. لذلك تتطلب أي عملية نشر نهائية مراجعة التكامل ضمن المستودع الأصلي وتشغيل الاختبارات أعلاه.
